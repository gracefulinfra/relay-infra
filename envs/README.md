# Environments

Each directory here is a Kustomize overlay that Argo CD's `relay-root` Application reconciles.
`platform/` holds only provider-neutral manifests. **Anything that differs by provider is patched in
here and nowhere else.** A new environment copies an overlay and changes the knobs below.

| Env | Status |
| --- | --- |
| `local` | k3d on a laptop (`make up`). Real values. |
| `local-b` | The second local "provider" for the portability rehearsal (P0-07, [docs/portability.md](../docs/portability.md)): its own k3d cluster, DNS suffix, CA and storage class, S3 outside the cluster over TLS, and PostgreSQL bootstrapped from the source's backups. `make portability` creates it. |
| `provider-a`, `provider-b` | Compile-only stubs (P0-05). Every provider value is a placeholder: an `*.example` domain (RFC 2606) or `PLACEHOLDER_*`. They become real when the owner picks providers; the portability scripts then run against them unchanged. |

`components/local-secrets` is shared by the laptop environments: the ESO Kubernetes provider over
`relay-secret-source`, and the local CA for `ClusterIssuer/relay-issuer`.

## Script settings: `env.sh`

Scripts never hardcode an environment. `scripts/lib.sh` sources `envs/$RELAY_ENV/env.sh` (default
`local`), which sets the cluster name, k3d config and registry, base domain, CA directory, and how to
reach S3 (`S3_MODE=in-cluster` or `external`, with endpoint, CA and state directory). It holds no secrets.
Where `env.sh` repeats an overlay value (the domain, the S3 endpoint pods use, the k3d network and
hostAliases), `make test` checks that the two agree. Envs without an `env.sh` (the provider stubs) are
render-only.

## Provider knobs

Each knob is listed with the base manifest it patches, what `local` sets, and what a provider overlay must set.

| Knob | Base manifest | `local` | Provider overlay |
| --- | --- | --- | --- |
| **Base domain** | `Gateway/relay` listener hostnames, every `HTTPRoute.spec.hostnames`, and Keycloak's `KC_HOSTNAME` (the first env var of `Deployment/keycloak`). The base placeholder is `relay.example.invalid` | `*.relay.localtest.me`, which public DNS resolves to 127.0.0.1 | The env's real wildcard domain |
| **DNS** | none (outside the cluster) | Nothing to do (localtest.me) | A wildcard record pointing at the load balancer (ExternalDNS or manual; not in this slice) |
| **Load balancer** | `EnvoyProxy/relay-proxy` `.spec.provider.kubernetes.envoyService` | `type: LoadBalancer` served by k3s klipper servicelb; k3d maps host ports 80/443 | The provider's LB annotations (scheme, IP family, health checks), and optionally `loadBalancerClass` |
| **TLS issuer** | `ClusterIssuer/relay-issuer` `.spec` (base is empty) | `ca:` over the script-generated local CA (`$RELAY_HOME/ca`, synced by `ExternalSecret/relay-local-ca`) | `acme:` with a DNS-01 solver (wildcards need DNS-01); the solver is provider-specific |
| **Secrets backend / KMS** | `ClusterSecretStore/relay-secrets` `.spec.provider` (base is empty) | ESO `kubernetes` provider reading `relay-secret-source`, which `scripts/secrets.sh` fills | The provider's secret manager (KMS-backed) or a Vault-API endpoint. `ExternalSecret`s never change; only the store does |
| **Storage class** | `Cluster.spec.storage.storageClass` (CNPG) and the SeaweedFS PVC | Unset, so k3s `local-path` (the default class) | The provider's block storage class (stubs: `PLACEHOLDER_STORAGE_CLASS`; `local-b`: `relay-b-retain`) |
| **S3 implementation** | `Application/seaweedfs` and `ExternalSecret/seaweedfs-s3-config` | SeaweedFS all-in-one with the four private buckets | Deleted: the provider's managed S3 is used, and its buckets are created out of band |
| **S3 endpoint** | `ObjectStore.spec.configuration.endpointURL` (CNPG backups, per namespace) and the `argo-workflows` `artifactRepository.s3.endpoint`/`insecure`; `S3_CLUSTER_ENDPOINT` in `env.sh` | `http://seaweedfs-all-in-one.seaweedfs.svc:8333` (plain HTTP inside the cluster) | The managed S3 endpoint over TLS (`local-b`: `https://s3.relay-b.internal:8443`) |
| **S3 CA** | `ObjectStore.spec.configuration.endpointCA` and `artifactRepository.s3.caSecret`, from the source key `s3-ca` | Unset | Only for an endpoint with a private CA (`local-b` sets both) |
| **Backup path** | `ObjectStore/relay-backups` `destinationPath` | `s3://relay-backups/cnpg/` | A restored environment archives next to, never into, the archive it recovered from (`local-b`: `cnpg-local-b/`) |
| **PostgreSQL bootstrap** | `Cluster.spec.bootstrap` | `initdb` | `recovery` from an origin `ObjectStore` for a restored environment (`local-b`); the recovery target is a run-time patch on `relay-root` (`ROOT_APP_PATCHES`) |
| **S3 credentials** | Source keys `s3-cnpg`, `s3-workflows`, `s3-otel`, `s3-admin` in the secret backend, each scoped to one bucket | Generated by `scripts/secrets.sh`; SeaweedFS IAM config built from them | Per-consumer credentials from the provider's IAM, stored in the secret manager under the same keys |
| **Keycloak test users** | `ExternalSecret/keycloak-test-users` and `users` in `platform/keycloak/realms/*.json` | Generated users `staff.test` (TOTP pre-enrolled) and `listener.test` (`local-b` receives them with the restored Keycloak database) | Must be removed before a real deployment (`docs/follow-ups.md`, P1-02); the stubs still render them |
| **Log shipping S3 endpoint** | `otel-collector` `config.exporters.awss3/logs.s3uploader.endpoint`/`disable_ssl` (placeholder `https://s3.example.invalid`) | `http://seaweedfs-all-in-one.seaweedfs.svc:8333`, `disable_ssl: true` | The managed S3 endpoint over TLS. With a private CA, mount `s3-ca` and set `AWS_CA_BUNDLE` (`local-b` does) |
| **Grafana URL** | `HTTPRoute/grafana` hostname and the `grafana` Application's `grafana.ini.server.root_url` | `grafana.relay.localtest.me` | `grafana.<env domain>` |
| **Workflow parallelism** | `argo-workflows` `controller.parallelism` | `1`: the laptop profile runs heavy jobs one at a time | Unset, or sized to the node pool |

Rules:

- A knob is added to this table in the same PR that introduces it.
- `platform/` must stay free of provider names, hostnames, and credentials. `make test` renders every
  overlay (provider stubs included) and validates it with kubeconform.
- Secrets are never in git in any form. A provider overlay points the `ClusterSecretStore` at its
  backend; the values are loaded there out of band.
